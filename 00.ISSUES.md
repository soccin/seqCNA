# seqCNA: Issues

IRIS / Slurm only, as of 6.0.0.

- Architecture and conventions: `CLAUDE.md`
- What changed, per release: `CHANGELOG.md`
- How the port was done, flag translation, resources, validation:
  `docs/SLURM_PORT.md`
- Cluster facts with job ids: `docs/IRIS_CLUSTER_INFO.md`
- The port specification and its decisions (D1 to D16):
  `00.SPEC_IRIS_PORT.md`

Labels: type (`bug`, `risk`, `docs`, `enhancement`, `cleanup`), priority,
`pre-port` where the defect existed under LSF and was carried over.
Numbered in order of work.

## Open

**#1 Output not compared with a JUNO run** (spec D12) · `risk` `high`
The test project (Proj_12257) is a first-time run, so the IRIS output
has no LSF-era reference. Find a previous seqCNA project whose BAMs
are reachable from IRIS, rerun it here and diff `_seqSeg.seg`,
`_seqSeg.out`, `bestMatches____out` and `GeneMatrix.csv` against the
delivered results (spec section 4, step 5). Package versions differ
(DNAcopy 1.84.0, pctGCdata 0.3.0, Rsamtools 2.26.0 under R 4.5.1), so
exact identity is not guaranteed; differences must stay below the
calling thresholds.

**#2 Mouse and sWGS paths untested on IRIS** (spec D12) · `risk`
`medium` The `mm10` relabel branch of `fixChromosomeNames.sh`, the
`Mouse-Twist` assay and `BINSIZE=auto` were ported without a run. Run
a mouse project and a shallow WGS project through `PIPE.sh` before
relying on them.

**#3 Pooled normals not on IRIS** (spec D10) · `docs` `medium` The
`IDT_Exome_v2_Normal` BAMs the README points at
(`~/Work/Pipelines/SeqCNV` on JUNO) have not been copied. Record the
IRIS path in `docs/IRIS_CLUSTER_INFO.md` and the README once they are.

**#4 `delivery.sh` not ported** (spec D16) · `enhancement` `medium`
It copies deliverables to the `/ifs/res` delivery tree of the old
servers. Out of scope for 6.0.0.

**#5 Genome tag mapping in three places** (spec D11) · `cleanup`
`low` `GenomeData/getGenomeBuildBAM.sh` (md5 to tag), `PIPE.sh` (tag
to assay before FIX, relabeled tag to `GENOME=` after FIX) and
`getGeneCalls.R` (`normalizeGenomeTag`). A `GENOMES.tsv` as in ChIP-seq
would replace the two `case` blocks. Not done in the port to keep the
diff reviewable.

**#6 `samples` file is written but unused** · `cleanup` `low`
`pre-port` `PIPE.sh` still writes `samples` from the BAM names for the
record, as the LSF version did; nothing reads it. The pair list is
`out/pipeline_info/pairs.tsv`.

**#7 Pair-stage memory is generous** · `cleanup` `low` COUNT and SEG
request `-M 8G` against peaks of 2.0 and 2.7 GB on 9 GB exome BAM
pairs (`docs/SLURM_PORT.md`). sWGS BAMs are larger; revisit after #2.

**#8 Usage errors leave no status file** · `docs` `low` `PIPE.sh`
with no argument or a bad assay type exits 1 before `00.RUNSTATUS.txt`
is written, so `bin/checkRun.sh` reports `NONE`. Same as ChIP-seq
issue #8; the control job log has the reason.
