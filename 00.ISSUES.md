**#5 Genome tag mapping in three places** (spec D11) · `cleanup`

**#7 Pair-stage memory is generous** · `cleanup` `low` COUNT and SEG
request `-M 8G` against peaks of 2.0 and 2.7 GB on 9 GB exome BAM
pairs; SEG peaked at 2.9 GB on the Proj_12257 pairs (up to 28 GB;
`docs/dev/SLURM_PORT.md`). sWGS BAMs are larger; revisit after #2.

**#8 Usage errors leave no status file** · `docs` `low` `PIPE.sh`
with no argument or a bad assay type exits 1 before `00.RUNSTATUS.txt`
is written, so `bin/checkRun.sh` reports `NONE`. Same as ChIP-seq
issue #8; the control job log has the reason.

**#10 Cancelling the control job is untested** (spec section 4, step
3) · `risk` `medium` `scancel` of the control job while stage jobs are
queued has not been run. Expect `FAILED` in `00.RUNSTATUS.txt` from
the EXIT trap and no stray jobs. The same trap is tested for a direct
run (SIGHUP, test13) and for a cancelled stage job (test03).

**#11 Superseded tidyverse calls, one undefined function** (spec
section 2.3) · `cleanup` `low` `summarize_at` and `spread`
(`getGeneCalls.R`, both `mkGeneAnnote.R`) still work under dplyr 1.2.1
and tidyr 1.3.2 but are superseded. `convert_mouse_to_human.R` calls
`first_UP()`, which is not defined, in `convert_human_to_mouse`, which
nothing calls.

**#12 IGV.seg rows are not sorted** · `cleanup` `low` `pre-port`
`postProcess.sh` concatenates the `.seg` files in the order `find`
lists them, so two runs with identical segments can write the rows of
`<ProjNo>___IGV.seg` in a different order (test31 and test32,
`docs/dev/SLURM_PORT.md`). The content is the same and IGV does not
depend on the order, but the files do not compare equal. Sort the file
list, or the rows by ID, chromosome and position.

**#1 Output not compared with a JUNO run** (spec D12) · `risk` `high`
· closed 2026-10-20: compared; the difference is a DNAcopy bug fix.
`../test20` reran a JUNO project (38 tumors x 20 normals, 760 pairs)
on IRIS beside its JUNO output. Counts, bin grid and `getGeneCalls`
match JUNO exactly; the segmentation does not (1,817 JUNO gene calls,
1,229 IRIS on the same pairs, 1,128 shared, none in the opposite
direction), so the acceptance in spec section 4 step 5 is not met as
run. The cause is DNAcopy 1.75.5, which fixed the weights passed to
each chromosome in weighted segmentation: the IRIS code with DNAcopy
1.60.0 reproduces every JUNO gene call. Decision: stay on the fixed
DNAcopy, do not back port; recorded in `CHANGELOG.md` and
`docs/methods.md`. Report:
`../test20/seqCNA_JUNO_vs_IRIS_concordance.html`.
