# seqCNA IRIS port: overview of the survey

Date: 2026-10-19. Full specification: `00.SPEC_IRIS_PORT.md`.

The survey is done and the spec is written for review. Nothing in the
repo has been changed; the spec and this file are the only new files.
The spec follows the ChIP-seq `00.SPEC` layout: findings, design,
validation, numbered decisions, work plan.

## Main result

The old R problem is smaller than feared. The only R 3.x artifact is
the committed `Rlib/seqDNAcopy` binary (built with R 3.5.1). The fork's
source was trial-built under R 4.5.1 into a scratch library in `/localscratch/soccin`.
It fails unpatched because IRanges no longer exports `RangesList`, and
installs and loads after changing that one word to `IRangesList` in the
submodule's NAMESPACE. DNAcopy, pctGCdata, and RJSONIO all install
cleanly. Everything else the scripts need is already in the R 4.5.1
library.

Recommendation: port to R 4.5.1. Hold conda R 3.6 as a fallback only if
validation shows numerical drift against JUNO results.

## What the three ports taught, applied to seqCNA

- Run `PIPE.sh` as a Slurm control job exactly as ATAC-seq and
  ChIP-seq do: `#SBATCH` header, launched with `~/bin/sbatch`, stage
  jobs through `~/bin/bsub`, each stage blocked with `bSync`/`bCheck`.
  PEMapper's up-front `afterok` chaining is not used (2026-10-19
  decision).
- Drop the `bsub -w post_done(...)` chain by making COUNT and SEG two
  stages, each a fan-out over all pairs followed by a wait.
- Vendor `slurmTools.sh`, `runStage.sh`, and `checkRun.sh` from
  ChIP-seq for waiting, sacct State checks, and log trailers.
- Known traps: `-W 24:00` means 24 minutes in Slurm; memory is a hard
  total cap; partial `--export` lists are broken on this cluster;
  `SBATCH_*` and `SLURM_*` must be scrubbed before submitting stage
  jobs; Slurm writes nothing into job logs, so trailers are required;
  check sacct State, never ExitCode.

## Items that need input (spec section 5, D1 to D16)

The ones that most affect the work:

- The Exome gene-call step reads two vcf2maf isoform override files
  that do not exist anywhere on IRIS. Proposal: vendor them from the
  vcf2maf v1.6.12 tag into `resources/`.
- ImageMagick is only available through a personal modulefile.
  Proposal: point at the shared install path from `bin/loadTools.sh`.
- Validation needs a JUNO result set to compare against. Is there a
  JUNO run of these 7 Proj_12257 BAMs, or any other project reachable
  from IRIS? Is a mouse project available for the mm10 path?
- Where the R package library should live: repo-local gitignored
  `Rlib/` built by a `00.SETUP.sh`, or the shared user library.
