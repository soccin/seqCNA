## 0. Summary

seqCNA can be ported to IRIS on the existing R 4.5.1 install. The only
R 3.x dependency is the committed `Rlib/seqDNAcopy` binary (built with
R 3.5.1). The fork's source builds and loads under R 4.5.1 after a
one-word NAMESPACE fix (`RangesList` -> `IRangesList`; the R code
already uses `IRangesList`). Its three dependencies that IRIS lacks
(DNAcopy, pctGCdata, RJSONIO) all install cleanly from Bioconductor,
GitHub and CRAN. A conda R 3.6 environment is therefore the fallback,
not the plan.

The scheduler work copies the ATAC-seq/ChIP-seq control-job pattern,
not PEMapper's dependency chaining:

- `PIPE.sh` becomes a Slurm control job with an `#SBATCH` header,
  launched through `~/bin/sbatch`.
- Each stage is a loop of `~/bin/bsub` submissions followed by
  `bSync`/`bCheck`. Stages: FIX, COUNT, SEG, BEST (in the control
  job), POST.
- The `bsub -w post_done(...)` chain is gone: COUNT and SEG are two
  stages, so no job depends on another job id.
- `bSync` and `parseLSF.py` are replaced by a vendored
  `bin/slurmTools.sh` (squeue wait + sacct State check + log trailer),
  copied from ChIP-seq.

Everything else is path and tool relocation, listed file by file in
section 2.3, plus a short list of pre-existing defects (2.5). The open
decisions are in section 5. Nothing starts until those are answered.

### 2.2 What the three ports have in common

All three were reviewed in detail. The points that matter for seqCNA:

1. **Control job.** ATAC and ChIP keep the sequential `pipe.sh` and run
   it as an sbatch job (`#SBATCH` header, `SLURM.CTRL/%j.out`). Under
   sbatch `$0` points at a spool copy, so `SDIR` cannot come from `$0`.
   They rely on the personal `~/bin/sbatch` wrapper, which bakes
   `SBATCH_SCRIPT_DIR` into a temp copy of the script. PEMapper's
   `downsampleBam.sh` avoids this: it self-submits with
   `sbatch --wrap "$SDIR/script.sh args"`, so the absolute path is in
   the command.
2. **Submission.** ATAC/ChIP call `bsub` through the `~/bin/bsub` shim.
   PEMapper calls `/usr/bin/sbatch` directly from a `QRUN` function in
   `bin/slurm.sh`. The shim has no `-R`, and its `-w` needs numeric job
   ids. PEMapper's doc explicitly rejected the shim for that reason.
3. **Dependencies.** Nobody uses name-based dependencies. ATAC/ChIP
   removed `-w post_done()` and sequence stages with `bSync`; PEMapper
   captures job ids and uses `--dependency=afterok:ID
   --kill-on-invalid-dep=yes`. Without the kill flag an orphaned child
   pends forever (`kill_invalid_depend` is off cluster-wide).
4. **Waiting and failure detection.** Slurm writes nothing into the
   job log. Every port adds an exit trailer (`#XXX_EXIT=<rc>`) via a
   `runStage.sh` wrapper and checks `sacct` State (never ExitCode: an
   OOM kill is `OUT_OF_MEMORY` with `ExitCode=0:125`). `bSync` became a
   squeue poll on an anchored job-name regex; `parseLSF.py` became
   `bCheck`/`bCheckAll` over sacct. sacct lags the queue, so checks
   retry.
5. **Flag translation.** `-W 24:00` is 24 hours in LSF and 24 minutes
   in Slurm. LSF `rusage[mem=N]` was per slot and advisory; `--mem` is
   the job total and a hard cap. `-n` must become `-c` (Slurm `-n` is
   tasks). `-o DIR/` must exist before submission or the job fails with
   no log.
6. **Environment leakage.** The default `--export=ALL` passes
   `SLURM_*` and `SBATCH_*` from the control job into stage jobs;
   `SBATCH_QOS=priority` then gets every short-partition job rejected.
   Every port unsets them before submitting. A partial `--export` list
   is broken on this cluster, so `ALL` is the only option.
7. **Walltime classes.** Jobs under 2h go to `cmobic_short,cpushort`
   (fast turnaround, qos must not be set); long jobs go to `cmobic_cpu`
   with `--qos=priority`. Walltimes sit just under the partition limit
   (1:55:00) because `EnforcePartLimits=ALL` rejects over-limit
   requests at submit time.
8. **Tools.** `bin/loadTools.sh` sources `/etc/profile.d/modules.sh` if
   `module` is not a function, loads pinned modules
   (`samtools/1.20`), checks each tool resolves, and sets `TMPDIR` to
   `/localscratch/$USER` (node /tmp is a shared 137G volume).
9. **R.** ATAC and ChIP use R 4.5.1 from PATH, set no `R_LIBS`, and
   install nothing by script. ChIP removed every `~/.Rprofile`
   dependency (`len`, `cc`, `DATE`, `getSDIR`) and runs
   `Rscript --no-init-file`. Neither built a package library; seqCNA is
   the first port that needs one.
10. **Docs.** A spec first (ChIP: `00.SPEC_v1.0.0.md` with numbered
    decisions), then `docs/SLURM_PORT.md` (translation tables,
    validation with job ids), `CHANGELOG.md`, a numbered issues file,
    `attic/` for retired files, and `CLAUDE.md` updated. Conventional
    commits with scope, `Co-Authored-By` trailer, `feat/...` branches
    merged to `devs` then `master`.
11. **Testing.** No test suites. Downsampled BAMs for smoke tests
    (`PEMapper/bin/downsampleBam.sh`), fresh `testNN` directories,
    deliberate failure injection, then a full-size run compared
    against the last JUNO output.

### 2.5 Pre-existing defects the port will expose or should fix

1. `PIPE.sh` deletes non-best pairs with `ls -d out/s_/*/*`. The
   scatter directory is the first two characters of the tumor id,
   which is `s_` only because every id starts with `s_`. Works, but
   should use the same `$scatter` logic as `seqCNA.sh` or `find`.
2. `PIPE.sh` writes `samples` from BAM basenames but nothing reads it
   downstream except the user. Keep, document.
3. `PIPE.sh` has no failure handling after `seqCNA.sh` submission
   besides `parseLSF.py`; a missing `.out` file is silently skipped by
   `selectBestMatch` (`parseSeqCNAOutFile` returns NULL). The new
   `bCheck` must fail the run on any non-COMPLETED pair job.
4. `exit -1` gives status 255. Use `exit 1`.
5. `fixChromosomeNames.sh` has `set -eu` but `PIPE.sh`, `seqCNA.sh`,
   `postProcess.sh` have no `set -e`; errors in `postProcess.sh`
   (e.g. `mkdir` of an existing dir, `fixXChrom.R` failing) do not
   stop the run.
6. `getGeneCalls.R` `quit()` on "no significant changes" exits 0 and
   leaves no `GeneMatrix.csv`; `delivery.sh` then fails on `cp`. Not a
   port issue; note in ISSUES.
7. The genome-tag mapping is split across `seqCNA.sh` (tag -> hg19/mm10)
   and `PIPE.sh` (tag -> assay). ATAC/ChIP moved this into one
   `lib/genomes/GENOMES.tsv`. Optional for this port (D11).
8. `getGITTag` runs `git describe` in `$SDIR` from compute nodes. Works
   (PEMapper confirmed no safe.directory issue), but the gitignored
   `Rlib/` must not make the tree look dirty (`-UNCOMMITED` suffix).

## 3. The port design

### 3.1 Strategy

Keep the pipeline shape. Change three things: how R is found, how jobs
are submitted and waited on, and where tools and resources live. No
algorithm changes. No restyling of untouched code.

New files (all under the repo):

```
00.SETUP.sh            build Rlib/ (R packages) once per checkout
bin/loadTools.sh       module bootstrap, samtools/1.20, ImageMagick path, R check, TMPDIR
bin/slurmTools.sh      seqSub, bSync, bCheck, bCheckAll, bKill (ChIP-seq's, CHIP_ -> SEQCNA_)
bin/runStage.sh        exit trailer + per-job TMPDIR (ChIP-seq's, renamed)
bin/checkRun.sh        0/1/2 verdict from status file + sacct + trailers (from ChIP-seq)
docs/SLURM_PORT.md     translation tables, environment, validation record
docs/IRIS_CLUSTER_INFO.md  cluster facts with job ids (copy PEMapper's, add seqCNA runs)
CHANGELOG.md, 00.ISSUES.md
```

Moved to `attic/`: `seqCNA.sh`, `GenomeData/genomeInfo_*.sh`, `testR`, `testR.R`,
`misc/INSTALL.RLIB`, `Rlib/INSTALL.md`, the old `Rlib/seqDNAcopy`
binary (or just deleted from git; it is recoverable from history).

### 3.2 R environment

- `00.SETUP.sh` (run once from the repo root, like ATAC/ChIP's venv
  setup): checks `Rscript` is 4.5.x and that DNAcopy, pctGCdata and
  RJSONIO load from the shared or personal library (fatal with an
  install hint otherwise), then installs `seqDNAcopy` from the
  submodule into `$SDIR/Rlib` (gitignored). Records versions in
  `Rlib/VERSIONS.txt`. Idempotent. (D2)
- `execWrapper.sh`: `export R_LIBS=$SDIR/Rlib:$R_LIBS`; remove the OS
  case; `RSCRIPT=$(command -v Rscript)`; fatal if `Rlib/seqDNAcopy`
  is missing ("run 00.SETUP.sh"). Keep `--vanilla` (the wrapped
  scripts never used `~/.Rprofile`).
- R is taken from PATH, as in ATAC/ChIP. `bin/loadTools.sh` checks the
  version and prints the path. No module load for R. (D1, D2)
- `seqDNAcopy` submodule: commit the NAMESPACE fix in
  `github.com/soccin/seqDNAcopy`, bump the submodule pointer. Version
  0.0.3 -> 0.0.4.
- `postProcess.sh` no longer switches R. `fixXChrom.R`,
  `getGeneCalls`, `plotSeg.R`, `redactNormals.R` all run under the same
  R 4.5.1.

### 3.3 Scheduler

The ChIP-seq/ATAC-seq control-job pattern, taken over as is. Not the
PEMapper pattern: PEMapper submits the whole DAG at once and encodes
the order in `afterok` job ids threaded from one `QRUN` call to the
next, so the run order is only visible by following ids, and inserting
a stage means re-plumbing them. Here the control script reads top to
bottom: each stage is a loop of submissions followed by one blocking
wait, and a new stage is a new loop.

**Control job.** `PIPE.sh` becomes the batch script, as `pipe.sh` is
in ChIP-seq:

```
sbatch seqCNA/PIPE.sh TARGETTED        # ~/bin/sbatch, from the project directory
seqCNA/bin/checkRun.sh                 # 0 done, 1 failed, 2 running, 3 sacct unavailable
```

- `#SBATCH` header: `-p cmobic_cpu --qos=priority -t 3-00:00:00 -c 2
  --mem=16G -J CTRL.seqCNA -o SLURM.CTRL/%j.out`. Slurm runs a spool
  copy, so `SDIR=${SBATCH_SCRIPT_DIR:-$(dirname $0)}`, with
  `SBATCH_SCRIPT_DIR` exported by `~/bin/sbatch`. Fatal if `$SDIR`
  does not contain `execWrapper.sh`.
- `source bin/loadTools.sh`, `source bin/slurmTools.sh`.
- `set -eu`; `00.RUNSTATUS.txt` (STATUS/STAGE/RC/MESSAGE, VERSION,
  CTRL_JOBID, GENOME, BINSIZE, ASSAY, SAMPLES) rewritten at every
  stage change; `SLURM.CTRL/jobs.tsv` with one line per stage job.
- `checkPreviousRun`: stop before writing anything if the directory
  holds `00.RUNSTATUS.txt`, `SLURM.CTRL/jobs.tsv`, `out/`, `outAll/`
  or `bamRelabel/`. One run per directory.
- EXIT trap: anything short of `RUN_DONE=1` writes `FAILED` plus the
  stage and a reason pulled from the failed jobs' logs, then `bKill`s
  every queued job of this run. TERM/INT traps for scancel and the
  time limit; `bSync` runs `bSync.sh` in the background and `wait`s so
  the trap fires promptly.
- `SLURM_*` (except `SLURM_CONF`) and `SBATCH_*` are unset before the
  first submission, so nothing of the control job rides into the stage
  jobs.

**Stage jobs.** `seqSub STAGE SAMPLE LOGDIR CLASS "BSUB_OPTS" CMD...`
(ChIP's `chipSub`, renamed) submits one job through `~/bin/bsub` as
`${TAG}_${STAGE}_$$`, wrapped in `bin/runStage.sh` (exit trailer
`#SEQCNA_EXIT=rc`, per-job TMPDIR under `/localscratch/$USER`), and
appends `JOBID STAGE SAMPLE LOG` to `jobs.tsv`. Classes as in ChIP:
`SHORT` = `-W 1:59:00`, no qos (lands on `cmobic_short,cpushort`);
`LONG` = `-W 12:00:00` with `SBATCH_QOS=priority` on that one call
(lands on `cmobic_cpu`). `waitStage STAGE` = `setStage`, `bSync` on
the anchored name, `bCheck` with the job count from `jobs.tsv`.

**Stages in PIPE.sh.** Each is "loop of seqSub, then waitStage":

| Stage | Jobs | Command | Class | Log dir |
|---|---|---|---|---|
| CHECK | none | genome of every BAM via `GenomeData/getGenomeBuildBAM.sh`, all equal; `tumors`/`normals` resolve to at least one BAM each; `samples` written | | |
| FIX | one per BAM | `fixChromosomeNames.sh BAM` (b37: symlink; others: reheader) | SHORT | SLURM.01.FIX |
| COUNT | one per tumor x normal | `getPairedCounts GENOME= TUMOR= NORMAL= ODIR= SAMPLEID=` | by BAM size (`runClass`), LONG until a rate is measured | SLURM.02.COUNT |
| SEG | one per pair | `seqSegment COUNTS=..._Counts.rda ODIR= BINSIZE=` | SHORT | SLURM.03.SEG |
| BEST | in the control job | `selectBestMatch out`, hard-link `outAll`, prune non-best pairs | | |
| POST | one job | `postProcess.sh ASSAY PROJNO` (fixXChrom, getGeneCalls, PNG to PDF with `convert`) | SHORT | SLURM.04.POST |
| STAGING | none | `bCheckAll "^${TAG}_.*_$$$"`, deliverables check, `STATUS=COMPLETED` | | |

COUNT and SEG are separate stages rather than one job per pair, so
each stage is one tool, as in ChIP-seq, and a segmentation problem is
re-run by hand from the existing `_Counts.rda` without recounting. The
cost is one more wait and twice the job count (10 pairs on the test
project; a 20 x 5 project would be 100 jobs per stage, well under the
array and queue limits). Alternative: `bin/runPair.sh` running both
tools in one job (D4).

`seqCNA.sh`, which submitted the `post_done` chain for one pair, goes
to `attic/`. Its two commands become the COUNT and SEG loops in
`PIPE.sh`. Single-pair hand runs call `getPairedCounts` and
`seqSegment` directly, as CLAUDE.md already documents.

Job names: `qSeqCNA_<STAGE>_<ctrl pid>`; every sacct query is bounded
by `SEQCNA_START`, exported before the first submission. Log
directories `SLURM.CTRL/`, `SLURM.01.FIX/` ... replace `LSF/`,
`LSF.FIX/`. `bSync`, `parseLSF.py`, `00_PIPE_DONE` are gone;
`bin/checkRun.sh` reads the status file, `jobs.tsv`, sacct and the
trailers instead.

Dependence on `~/bin` (`bsub`, `sbatch`, `bSync.sh`) is accepted, as
in ATAC-seq and ChIP-seq, and recorded in `docs/IRIS_CLUSTER_INFO.md`
with the shim patches the pipeline relies on (`-W` to `-t`, `-M` to
`--mem`, `-o DIR/`, partition defaults).

## 4. Test data and validation

Test project: the parent directory (Proj_12257, b37 exome, 5 tumors x 2
normals = 10 pairs, BAMs about 4 GB each, `.bai` present, no
`*request.txt`, so the project id comes from the path). This is enough
for a full end-to-end run; a 1/20 downsample via
`PEMapper/bin/downsampleBam.sh` gives a 5-minute smoke test.

Validation steps, in order:

1. `00.SETUP.sh` checks `RJSONIO`, `DNAcopy`, `pctGCdata` load, then
   builds `Rlib/seqDNAcopy`; `testR`-style load check.
2. `getPairedCounts` + `seqSegment` by hand on one pair, foreground,
   R 4.5.1. Confirms the R path end to end and gives first memory and
   time numbers.
3. Smoke run of `PIPE.sh TARGETTED` on downsampled BAMs in a fresh
   `test01/`. Failure injection: one BAM without index, scancel of a
   PAIR job, scancel of the control job. Check `00.RUNSTATUS.txt`,
   `bin/checkRun.sh`, logs and trailers.
4. Full-size run on the 7 BAMs. Record job ids, sacct MaxRSS and
   Elapsed in `docs/IRIS_CLUSTER_INFO.md`; set the default memory and
   walltime class from them.
5. Comparison with JUNO output of previous seqCNA projects (D12; not
   Proj_12257, which has no prior run): per pair, diff of `_seqSeg.seg`
   (segment boundaries and `seg.mean`), `_seqSeg.out` QC metrics,
   `bestMatches____out`, `GeneMatrix.csv`. Acceptance: identical
   segment tables, or differences explained by package versions and
   below the calling thresholds (`|seg.mean| > 1`, FDR 0.05) for every
   gene call.
6. Mouse path (`Mouse-Twist`, mm10 relabel): needs a mouse project
   among the previous runs found for D12. Listed as "not tested" in
   the CHANGELOG otherwise.

## 5. Decisions

All resolved 2026-10-20.

- **D1. R version.** R 4.5.1 from PATH (Path A). Conda R 3.6 is not
  used.
- **D2. Package library location.** Repo-local `seqCNA/Rlib`,
  gitignored, built by `00.SETUP.sh`. The committed R 3.5.1 binary
  `Rlib/seqDNAcopy` is removed. `Rlib` holds only `seqDNAcopy`; the
  common packages `RJSONIO`, `DNAcopy`, `pctGCdata` come from the
  shared/personal R 4.5.1 library (`RJSONIO` 2.0.5 is already there;
  `DNAcopy` and `pctGCdata` still to be installed by the user).
  `00.SETUP.sh` checks all three are loadable before building.
- **D3. RJSONIO.** Keep RJSONIO.
- **D4. Pair stages.** Two stages, COUNT then SEG, one job per pair in
  each, each followed by `bSync`/`bCheck`. No `bin/runPair.sh`.
- **D5. Submission primitive.** `~/bin/bsub` through `seqSub`, as
  ATAC-seq and ChIP-seq.
- **D6. Control job launch.** `#SBATCH` header in `PIPE.sh`, launched
  with `~/bin/sbatch seqCNA/PIPE.sh ...`, `SDIR` from
  `SBATCH_SCRIPT_DIR`. Dependence on `~/bin` documented in
  `docs/IRIS_CLUSTER_INFO.md`.
- **D7. ImageMagick.** `bin/loadTools.sh` prepends the shared
  `/usersoftware/core001/common/RHEL_8/imagemagick/7.1.2-33/bin`.
- **D8. Exome isoform overrides.** Vendor the two vcf2maf v1.6.12
  files into `resources/vcf2maf/v1.6.12/`; record source and md5 in
  the CHANGELOG.
- **D9. `~/.Rprofile` dependence.** `redactNormals.R` uses
  `openxlsx::write.xlsx` directly; standalone scripts run with
  `Rscript --no-init-file`.
- **D10. Pooled normals.** `IDT_Exome_v2_Normal` BAMs are not on IRIS
  yet; they will be copied later. `docs/IRIS_CLUSTER_INFO.md` gets a
  placeholder entry for the path.
- **D11. Genome table.** Not in this port. The md5 -> tag -> genome ->
  assay mapping moves from `seqCNA.sh` into `PIPE.sh` unchanged, with
  a comment cross-referencing `getGenomeBuildBAM.sh`.
- **D12. Reference results.** Proj_12257 is a first-time run, so it
  has no JUNO output; it is the run-to-completion test. The user will
  locate previous seqCNA projects with JUNO output and BAMs reachable
  from IRIS; those are the comparison set. Mouse coverage depends on
  what is found.
- **D13. Resource requests.** COUNT and SEG `-c 2 --mem=32G`, FIX
  `-c 1 --mem=4G`, POST `-c 1 --mem=8G`, control `-c 2 --mem=16G`
  3 days qos priority. Measure with sacct MaxRSS/Elapsed on the first
  full run and tighten.
- **D14. Scope of R cleanup.** Port-only changes to R files (library
  path, isoform path, NAMESPACE, `write_xlsx`, R 4 breakage if any).
  No restyle.
- **D15. Branch and version.** Branch `feat/iris` off `devs` (created
  now); the pre-port head is branch `juno` (3e6c18d), also tagged
  `v5-juno` (annotated, added after this decision); bump `VERSION` to
  `6.0.0` when commits are requested; merge `feat/iris` -> `devs` ->
  `master` when validated (done through the release branch
  `rel/v6.0.0`).
- **D16. Delivery.** `delivery.sh` and the `/ifs/res` delivery path
  are out of scope. Only D9 touches delivery tooling.
